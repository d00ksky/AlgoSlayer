# Local Development Workflow

Use this guide when you (or a Codex agent running on your Mac) want to work on AlgoSlayer locally. It assumes macOS with Python 3.12+ and 16 GB RAM.

## 1. Clone & Environment

```bash
git clone git@github.com:your-username/AlgoSlayer.git
cd AlgoSlayer

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install pytest pytest-asyncio
```

> Keep the `.venv/` inside the repo root so the Codex CLI can reuse it between sessions.

## 2. Optional Heavy ML Extras

Install these only when you plan to run the heavyweight training cycle.

```bash
# Apple Silicon
pip install tensorflow-macos==2.15.0 tensorflow-metal==1.1.0 xgboost==2.1.1

# Intel macOS
pip install tensorflow-cpu==2.16.1 xgboost==2.1.1
```

## 3. Running Tests

```bash
# Fast deterministic sanity checks (default)
pytest -q

# Full integration suite (needs live services + heavy deps)
RUN_FULL_SUITE=true pytest -q
```

The default configuration skips long-running integration scripts, so the suite finishes in a few seconds. Set `RUN_FULL_SUITE=true` only when the Mac has network access to IBKR/yfinance and sufficient memory (>8 GB free).

## 4. Heavy Training Cycle

Follow `docs/local_training.md` for the end-to-end process: sync data from the server, run `enhanced_hybrid_coordinator.py --train`, review metrics, and deploy models back. The heavy cycle benefits from the optional TensorFlow/XGBoost extras above.

## 5. Common Developer Commands

```bash
# format (if Black is installed)
black src tests

# static analysis (optional)
flake8 src tests

# run paper-trading server locally
USE_OPTIONS_SYSTEM=true TRADING_ENABLED=false python run_server.py
```

## 6. Syncing With the Server

- Use `git pull` before each session.
- Keep `.env` out of version control; copy from `env_template.txt` if needed.
- To inspect production data, rely on the helper scripts in `hybrid_work/` generated by the coordinator.

## 7. Clean-up Checklist

- Deactivate the venv when finished: `deactivate`.
- Remove large artifacts (e.g., `hybrid_work/server_data_latest.db`) if space becomes tight.
- Commit and push only the files you intentionally changed; avoid staging server backups or `.venv/`.
